TypeScript en el navegador

Configura, compila y lleva tu código tipado a una página real: el proyecto práctico final del tema.

tsconfig: el mapa del proyecto

tsconfig.json reúne todas las opciones del compilador. Los campos que más usarás son:

{
  "compilerOptions": {
    "target": "ES2020",    // versión JS de salida
    "module": "ES2020",   // soporta import / export
    "outDir": "./dist",   // donde se genera el JS
    "strict": true        // máxima seguridad de tipos
  },
  "include": ["src"]        // carpetas que se compilan
}
Tip: deja strict: true desde el día uno. Con strict activado, null y undefined no se asignan en silencio a variables que esperan un valor.

Compilar a JavaScript

Todo el flujo se reduce a un comando. Escribe en src/ y el JS generado aparece en dist/:

# compilar una vez
$ npx tsc

# compilar y regenerar en cada cambio
$ npx tsc --watch

El resultado es JavaScript idéntico en comportamiento, sin anotaciones ni interfaces:

// src/app.ts (lo que escribes)
interface Persona {
  nombre: string;
  edad: number;
}
const persona: Persona = { nombre: "Ana", edad: 28 };
// dist/app.js (lo que genera tsc)
const persona = { nombre: "Ana", edad: 28 };
La interfaz desaparece, el valor queda

Ese es el contrato mental: TypeScript solo existe en desarrollo. Lo que se despliega es el JS puro generado, rápido y sin dependencias en tiempo de ejecución.

TypeScript en el HTML

El navegador no entiende TypeScript: cargas el archivo compilado. Enlaza el JS generado como un módulo normal:

<script type="module" src="./dist/app.js"></script>
¿Por qué <script type="module">? porque así tu proyecto puede usar import y export entre archivos, tal como lo escribes en TypeScript con module: "ES2020".

Con un servidor local (por ejemplo npx serve) solo apuntas al archivo generado:

# sirve la carpeta del proyecto
$ npx serve .

# abre http://localhost:3000 con tu index.html ya compilado

Proyecto mínimo de referencia

Así se ordena un proyecto TypeScript para web. Separa el código fuente (donde escribes tipos) del código servido (el JS compilado):

mi-proyecto/
  src/           # tus archivos .ts
    app.ts
  dist/          # JS generado por tsc
    app.js
  index.html      # carga dist/app.js
  tsconfig.json
Error frecuente: enlazar directo src/app.ts en el HTML. El navegador no lo ejecutará. Siempre compila primero y enlaza la versión de dist/.

Práctica final

Construye un mini registrador de tareas tipado siguiendo estos pasos:

  1. Crea src/tareas.ts con la interfaz Tarea (id, titulo, completada).
  2. Anota un array tareas: Tarea[] y una función agregarTarea(titulo: string): void.
  3. Escribe una función marcarCompletada(id: number): void que recorra el array.
  4. Usa el DOM para pintar cada tarea y escuchar el clic en los botones.
  5. Compila con npx tsc y sirve la carpeta: tu tipado controla cada dato que entra a la página.

Repaso rápido

  • tsconfig.json centraliza opciones: strict, outDir, target.
  • npx tsc valida tipos y genera el JS; npx tsc --watch lo hace en cada cambio.
  • El navegador solo ve JS: enlaza <script type="module" src="./dist/...js">.
  • Separa src/ (tipado) de dist/ (lo desplegable).
