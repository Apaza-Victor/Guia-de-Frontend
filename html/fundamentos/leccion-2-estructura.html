Estructura Base del Documento

Domina el <head>, las metas SEO, encoding y cómo los navegadores leen tu HTML.

Fundamentos de la lección

Todo documento HTML real tiene dos grandes bloques: el <head>, que guarda información invisible pero crítica (metadatos, estilos, SEO y configuración), y el <body>, donde vive todo el contenido visible. Entender esta anatomía te permite diagnosticar desde el primer día problemas de carga lenta, posicionamiento en Google o páginas "rotas" en móviles.

Conceptos clave

<head> vs <body> meta charset y viewport defer en los scripts

Anatómía del documento

Un documento HTML de producción real tiene más de lo que viste en la lección 1. Esta es la versión profesional:

<!DOCTYPE html>
<html lang="es">

  <head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <meta name="description"
          content="Descripción corta y atractiva para SEO">
    <title>Mi sitio profesional</title>
    <link rel="stylesheet" href="css/style.css">
    <link rel="icon" href="favicon.ico">
    <!-- Open Graph: cómo se ve al compartir en redes -->
    <meta property="og:title" content="Mi sitio">
    <meta property="og:image" content="img/portada.png">
  </head>

  <body>
    <!-- Contenido visible -->
  </body>

  <script src="js/app.js" defer></script>
</html>

Dentro del <head> en detalle

Meta / ElementoPropósito
<meta charset="UTF-8">Soporta todos los caracteres, acentos y emojis
<meta name="viewport">Diseño responsive en móviles (imprescindible)
<meta name="description">Resumen mostrado por Google en los resultados
<title>Título de la pestaña y encabezado SEO
<link rel="stylesheet">Carga un archivo CSS externo
<link rel="icon">Favicon (icono de la pestaña)
Open Graph (og:*)Preview atractivo al compartir en redes
Clave: sin la etiqueta <meta name="viewport"> tu página se verá "engordada" y rota en celulares. Siempre inclúyela.

<body> y orden de carga del contenido

Los navegadores leen el HTML de arriba a abajo (streaming). El orden importa para el rendimiento:

  • Primero el <head> (metadatos + CSS para no saltar estilos).
  • Después el <body> (contenido visible).
  • Al final los <script> con el atributo defer para no bloquear la pintura de la página.
<script src="app.js" defer></script>
<script src="app.js" async></script>
defer

Descarga en paralelo y se ejecuta al final. Mantiene el orden de los scripts. Opción recomendada.

async

Descarga en paralelo y se ejecuta apenas llega. Útil solo cuando el orden no importa.

Repaso rápido

  • El <head> nunca se ve; contiene metadatos, CSS y config de SEO.
  • viewport es obligatorio para móviles; description para SEO.
  • Coloca los scripts al final con defer para no bloquear la página.
