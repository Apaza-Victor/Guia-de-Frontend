Tipos avanzados

Arrays, tuplas, objetos tipados, uniones y alias para modelar datos reales de forma precisa.

Arrays y tuplas

Un array tipado declara el tipo de todos sus elementos: string[] es un array donde solo entran textos.

let frutas: string[] = ["manzana", "pera"];
let notas: number[] = [18, 16, 20];
let mixto: (string | number)[] = ["a", 1, "b"];
// frutas.push(42);  Error: solo admite strings

La tupla fija el tipo y la posición de cada elemento, útil para coordenadas o pares clave-valor:

let coordenada: [number, number] = [-12.04, -77.04];
let usuario: [string, number] = ["ana", 28];
let [nombre, edad] = usuario;  // desestructuración tipada
Nota: escribe (string | number)[] cuando el array mezcla tipos, y string[] cuando solo guarda uno. El orden de los corchetes cambia el significado.

Objetos tipados inline

Puedes describir un objeto directamente en la anotación, sin crear nada más:

let producto: {
  nombre: string;
  precio: number;
} = {
  nombre: "Teclado",
  precio: 89.5,
};
// producto.precio = "barato";  Error: precio debe ser number
Ojo: el objeto debe cumplir el molde exacto. Si falta una propiedad (precio) o sobra otra no declarada, TypeScript marca el error al asignar.

Uniones

El operador | permite que un valor acepte varios tipos. Con literales tipados, además, solo admites valores concretos:

let id: string | number = "abc-123";
id = 42;  // OK, admite ambos tipos

let estado: "pendiente" | "pagado" | "cancelado" = "pendiente";
estado = "pagado";  // OK, es un valor permitido
// estado = "enviado";  Error: no está en la unión

Las uniones con literales son perfectas para estados de pedidos, niveles de permisos o resultados de una validación.

Alias con type

Cuando un tipo se repite, dale un nombre con type y reutilízalo en todo el proyecto:

type Id = string | number;
type Coordenadas = [number, number];
type EstadoPedido = "pendiente" | "pagado" | "cancelado";

function buscar(id: Id): void {
  // cuerpo de la función
}
Tip: los alias no generan código en el JS final: desaparecen al compilar y solo existen para que tú y el editor entiendan mejor los datos.

any vs unknown

Ambos aceptan cualquier valor, pero se comportan de forma muy diferente:

TipoComportamiento
anyDesactiva el chequeo: puedes llamar métodos sin que nadie te detenga. Pierde toda la seguridad.
unknownGuarda el valor pero obliga a verificar antes de usarlo. Es el "tipo desconocido" seguro.
 
let dato: unknown = "texto";
// dato.length -> Error: no se puede usar sin verificar

if (typeof dato === "string") {
  console.log(dato.length);  // OK, ya verificado
}
Regla práctica: si algo llega de una API o de un input del usuario, no lo declares any. Usa unknown y verifica antes de usar, u obliga el molde con as.

Repaso rápido

  • string[] tipa arrays; [number, number] tipa tuplas de posición fija.
  • Los objetos admiten anotación inline con nombre y tipo por propiedad.
  • | crea uniones y type les da un nombre reutilizable.
  • Prefiere unknown sobre any: obliga a verificar el valor antes de usarlo.
