Contenido e integraciones

Escribe en Markdown, organiza con Content Collections y conecta integraciones oficiales e islas de interacción.

Contenido con Markdown

Astro entiende Markdown de forma nativa. Escribe un archivo .md con frontmatter y Astro lo convierte en HTML durante el build, sin base de datos ni CMS.

---
titulo: "Mi primer post con Astro"
fecha: 2026-09-16
descripcion: "Contenido en Markdown renderizado como HTML estático."
---

Astro convierte este **Markdown** en HTML al compilar.
Puedes usar listas, imágenes, enlaces y hasta componentes `.astro`.

- Escribes en texto plano
- Astro genera el HTML final
- El visitante recibe HTML puro, sin JS innecesario
---
// src/pages/blog/index.astro: lista todos los posts
import { getCollection } from "astro:content";
const posts = await getCollection("blog");
---

<ul>
  {posts.map((post) => (
    <li>
      <a href={`/blog/${post.slug}`}>{post.data.titulo}</a>
    </li>
  ))}
</ul>

Content Collections

Una Content Collection es una carpeta de contenido con un esquema definido. Cada post debe cumplirlo; si falta el campo obligatorio, el build falla y te avisa.

// src/content.config.ts
import { defineCollection, z } from "astro:content";

const blog = defineCollection({
  type: "content",
  schema: z.object({
    titulo: z.string(),
    fecha: z.date(),
    descripcion: z.string().optional()
  })
});

export const collections = { blog };
ConceptoQué hace
defineCollectionDefine una colección tipada de contenido.
type: "content"Los archivos son Markdown/MDX con frontmatter.
z.object(...)Validación del frontmatter con Zod.
getCollectionConsulta los documentos de una colección.
Tip: Las collections convierten tu blog en un sistema con tipos: el editor se queja en el momento si olvidas un campo, antes de desplegar.

Integraciones oficiales

Las integraciones añaden capacidades a Astro con un comando: Tailwind, React, Preact, Svelte, Vue, sitemap, MDX... La CLI las instala y las registra automáticamente en astro.config.mjs.

npx astro add tailwind
npx astro add react
npx astro add sitemap

# Cada comando instala el paquete y actualiza astro.config.mjs por ti
// astro.config.mjs después ejecutar astro add tailwind
import { defineConfig } from "astro/config";
import tailwind from "@astrojs/tailwind";

export default defineConfig({
  integrations: [tailwind()]
});
¿Qué es @astrojs/tailwind?

La integración oficial de Tailwind para Astro: procesa las clases de tus componentes y layouts al construir. Es exactamente lo que usarás en la Lección 5 para la landing final.

Islas de interacción

Para que un componente tenga JavaScript en el navegador, lo marcas como isla con un atributo client:*. Astro hidrata solo esa pieza; el resto sigue siendo HTML estático.

DirectivaCuándo se hidrata
client:loadInmediatamente al cargar la página.
client:idleCuando el navegador está libre de tareas.
client:visibleCuando el componente entra en el viewport.
client:onlySe renderiza solo en el navegador.
 
---
import Contador from "../components/Contador.jsx";
import MenuMovil from "../components/MenuMovil.astro";
---

<!-- Isla con React, hidratada al instante -->
<Contador client:load />

<!-- Isla de Astro pura, hidratada al asomarse -->
<MenuMovil client:visible />
Concepto clave: sin client:*, un componente se renderiza en el servidor y llega como HTML "muerto". La directiva es justamente lo que lo "enciende" en el navegador.
