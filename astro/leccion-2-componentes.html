Componentes .astro y props

Aprende la anatomía de un componente: frontmatter, template, props y estilos que no se filtran a nadie más.

Anatomía de un componente .astro

Un archivo .astro tiene tres partes: el frontmatter (JavaScript entre dos líneas de guiones), el template (HTML con expresiones entre llaves) y, opcionalmente, uno o más <style>.

---
// 1) Frontmatter: JavaScript que corre en la construcción
const titulo = "Hola, Astro";
const items = ["Uno", "Dos", "Tres"];
---

<!-- 2) Template: HTML con expresiones entre llaves -->
<article class="tarjeta">
  <h2>{titulo}</h2>
  <ul>
    {items.map((item) => <li>{item}</li>)}
  </ul>
</article>

<!-- 3) Estilos scoped: solo afectan a este componente -->
<style>
  .tarjeta { border: 1px solid #334155; padding: 1rem; }
</style>
Digestión mental

El frontmatter se ejecuta una vez, en la compilación. El template es HTML con lo que las variables ya calculadas le inyectan. No hay "estado" que mantener en el servidor.

Props con Astro.props

Para hacer componentes reutilizables, necesitas recibir datos de quien los usa. Todo lo que pase por atributos llega a Astro.props. Con TypeScript puedes definirlas y darles valores por defecto.

---
// src/components/TarjetaUsuario.astro
interface Props {
  nombre: string;
  avatar?: string;
}

const { nombre, avatar = "/default.png" } = Astro.props;
---

<figure class="usuario">
  <img src={avatar} alt={nombre} />
  <figcaption>{nombre}</figcaption>
</figure>
PatrónEfecto
{ nombre, avatar } = Astro.propsDesestructura las props recibidas.
avatar = "/default.png"Valor por defecto si no llega la prop.
{titulo} en el templateInterpola la variable en el HTML.
Tip: Definir la interfaz Props te da autocompletado y detecta errores de props en tu editor aunque el archivo sea .astro.

Estilos scoped

El CSS que escribes dentro de un <style> de un componente .astro se aisla automáticamente: Astro le añade un atributo único por clase y tus estilos no contaminan el resto del sitio.

<style>
  .usuario { display: flex; gap: 1rem; padding: 1rem; }
  .usuario img { width: 48px; border-radius: 50%; }
</style>

<!-- En el navegador, Astro reescribe los selectores: -->
<style>
  .usuario:where(.astro-abc123) { ... }
</style>
Atención: si quieres un estilo global, usa el atributo <style is:global>. El resto del CSS hereda el aislamiento automático.

Reutilización de componentes

Importa tus componentes en otros archivos y pásales props como si fueran elementos HTML. Un botón, una tarjeta o un header se montan una vez y se reutilizan en todas las páginas.

---
import TarjetaUsuario from "../components/TarjetaUsuario.astro";
import Header from "../components/Header.astro";
---

<Header titulo="Nuestro equipo" />
<main>
  <TarjetaUsuario nombre="Ana" avatar="/img/ana.png" />
  <TarjetaUsuario nombre="Bruno" avatar="/img/bruno.png" />
</main>
Tip: Los nombres de las props se escriben en camelCase; en el componente receptor las lees igual con Astro.props.

Demo: componente contador

Un contador necesita JavaScript en el navegador. En Astro lo envuelves en una isla; aquí lo simulamos con un pequeño script para sentir el patrón cliente/servidor.

Cuenta clicks como si fuera un componente hidratado con client:load. El HTML inicial llega estático y el script le da vida.

---
// En un componente "isla", el script se envía al cliente
let clicks = 0;

<button id="btnContador">{clicks} clicks</button>

<script>
  const btn = document.getElementById('btnContador');
  btn.addEventListener('click', () => {
    btn.textContent = (btn.textContent.replace(' clicks', '') * 1 + 1) + ' clicks';
  });
</script>

Repaso rápido

  • Un componente .astro = frontmatter + template + estilos scoped.
  • Astro.props recibe los datos; la interfaz Props los tipa.
  • El CSS de un <style> queda aislado; is:global lo desactiva.
  • Los componentes se importan y reutilizan pasándoles props como atributos.
