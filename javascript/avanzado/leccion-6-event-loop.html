El Event Loop

El porqué del orden de las promesas, los intervals y los eventos.

Un solo hilo, una sola cola

JavaScript en el navegador es monohilo: ejecuta una instrucción a la vez. Todo lo que escribes (calls a funciones, bucles, condicionales) se apila en el call stack. Cuando el stack se vacía, la página queda "libre" para reaccionar a clics, teclas y animaciones.

Ojo: Un bucle infinito o una función que tarda segundos bloquean la UI: los clics quedan congelados. Por eso las tareas lentas se delegan a la asincronía.

Las funciones que "esperan" (setTimeout, fetch, promesas, eventos) no bloquean: se desvían a las Web APIs del navegador y vuelven a través de colas.

Task queue vs microtask queue

El Event Loop no es una sola cola: hay dos prioridades. Las promesas saltan primero.

Microtasks (prioridad alta)

callbacks de promesas: .then, .catch, await, queueMicrotask.

Task queue (prioridad normal)

timers, eventos, I/O, setTimeout e setInterval.

El orden siempre es: 1) código síncrono, 2) todas las microtasks pendientes, 3) una tarea y se repite. Las microtasks se vacían por completo antes de mirar las tareas:

setTimeout(() => console.log('A'), 0);
Promise.resolve()
  .then(() => console.log('B'));

// Orden real: B, luego A

Recetario de orden de ejecución

  • Síncrono se ejecuta siempre primero, en el orden escrito.
  • await pausa la función actual y mete el resto en la microtask queue.
  • Varias promesas seguidas se ordenan por tiempo de resolución, no por el orden del código.
  • setTimeout(fn, 0) no es "inmediato": pasa después de todas las microtasks.
  • Dos setInterval iguales se alternan según llegaron, con un mínimo de 4 ms entre tareas.
Tip: Para depurar, reemplaza la intuición por experimentos: abre DevTools → Console y escribe el fragmento para ver el orden real con tus ojos.

Demo: adivina el orden

Antes de pulsar, piensa el orden que crees que verás. Luego pulsa "Ver el orden": 

console.log('1 síncrono');
Promise.resolve().then(() => console.log('2 micro'));
setTimeout(() => console.log('3 task'), 0);
console.log('4 síncrono');

    1 y 4 salen al instante; el 2 se descarga de microtasks antes que el 3, aunque el 3 parecía "más urgente".

    Ojo: No abuses de la microtask queue: una tarea que await en cadena "roba" tiempo a las tareas normales (rendering, eventos) si encadenas miles de microtasks de golpe.

    Repaso rápido

    • JavaScript es monohilo: call stack + Event Loop.
    • Las microtasks (promesas/await) tienen prioridad sobre las tareas (timers/eventos).
    • setTimeout(fn, 0) NO es inmediato: corre tras las microtasks.
    • Orden típico: síncrono → todas las microtasks → una tarea → repite.
