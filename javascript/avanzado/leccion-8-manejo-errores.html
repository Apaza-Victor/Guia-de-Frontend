Manejo de errores

Lanzo, capturo y clasifico errores como un profesional.

throw y los tipos de error

throw interrumpe la ejecución y entrega un valor (normalmente un Error) que el try/catch más cercano puede capturar. JavaScript trae errores nativos:

TipoCuándo aparece
SyntaxErrorcódigo mal escrito (no compila)
TypeErrorusas un tipo indebido (ej. undefined())
ReferenceErrorvariable no declarada
RangeErrorvalor fuera de rango ([].length = -1)
CustomError (tuyo)reglas de negocio o validación
 
if (edad < 18) {
  throw new Error('Debes ser mayor de edad');
}

try / catch / finally

La estructura completa tiene tres bloques con funciones bien distintas: 

try {
  // código que puede fallar
  iniciarConexion();
} catch (error) {
  // solo corre si hubo error
  console.error('No se pudo conectar', error);
} finally {
  // SIEMPRE corre, haya o no error
  cerrarConexion();
}

finally es ideal para limpieza: cerrar sockets, resetear flags, limpiar timers. Se ejecuta incluso si haces return dentro de try.

Ojo: Capturar y tragarse el error (catch (e) {}) dificulta el debugging. Como mínimo registra el error; idealmente, decide si se puede continuar o hay que avisar al usuario.

Errores personalizados

Para código grande, clasificar errores ahorra horas. Extiende Error con tus propias clases y distíngelas con instanceof: 

class ValidacionError extends Error {
  constructor(campos, mensaje = 'Datos inválidos') {
    super(mensaje);
    this.name = 'ValidacionError';
    this.campos = campos;   // ej. ['email', 'password']
  }
}

class ApiError extends Error {
  constructor(status, mensaje = 'Error del servidor') {
    super(mensaje);
    this.name = 'ApiError';
    this.status = status;
  }
}

En un catch puedes separar los caminos:

} catch (error) {
  if (error instanceof ValidacionError) {
    pintarErrores(error.campos);
  } else if (error instanceof ApiError) {
    avisar('Servidor respondió ' + error.status);
  } else {
    console.error('Inesperado', error);
  }
}
Tip: En errores anidados, encadena causa con { cause: errorOriginal } (new ApiError(500, 'Boom', { cause: original })) y llega siempre a un catch raíz.

Ojo: En producción, un error NO capturado en una promesa o un evento dispara unhandledrejection / window.onerror. Pon handlers globales que registren el incidente en tu herramienta de monitoreo.

Repaso rápido

  • throw para detener y entregar el error; try/catch/finally para manejarlo.
  • Clasifica con errores personalizados (extends Error) y instanceof.
  • finally corre siempre: úsalo para limpieza.
  • No tragues errores y registra siempre; añade handlers globales para lo inesperado.
