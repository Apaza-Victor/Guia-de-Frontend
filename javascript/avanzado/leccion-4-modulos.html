Módulos ES y closures

Divide tu código en archivos independientes y encapsula estado con closures.

¿Qué son los módulos ES?

Un módulo es un archivo JavaScript que exporta valores y importa los de otros. ES6 aportó la sintaxis import/export, que hoy es el estándar en el navegador (con la etiqueta <script type="module">), en Node.js y en todos los bundlers (Vite, Webpack).

Beneficios: separación de responsabilidades, reutilización real, árbol de dependencias claro y scope propio (cada módulo tiene su propio ámbito, nada se filtra al global). 
// utilidades.js — EXPORTA
export function formatearFecha(fecha) { /* … */ }

export const MIN_PASS = 8;
export const CONFIG = { tema: "oscuro", lengua: "es" };

// Export por defecto (solo uno por módulo)
export default function print(v) { console.log(v); }
// app.js — IMPORTA
import print from "./utilidades.js";                    // default (nombre libre)
import { formatearFecha, MIN_PASS } from "./utilidades.js";
import * as util from "./utilidades.js";            // todo el módulo

Múltiples módulos: proveedor de datos

// api.js
export async function obtenerUsuarios() {
  const res = await fetch("/api/usuarios");
  if (!res.ok) throw new Error("Error de red");
  return res.json();
}

// ui.js
export function pintarUsuarios(lista) {
  renderizar(lista.map(u => u.nombre));
}

// main.js (punto de entrada)
import { obtenerUsuarios } from "./api.js";
import { pintarUsuarios } from "./ui.js";

obtenerUsuarios()
  .then(pintarUsuarios)
  .catch(err => console.error(err));

Closures: memoria que no se escapa

Un closure es una función que recuerda las variables del ámbito donde fue creada, incluso después de que ese ámbito haya terminado. Es la base para encapsular estado "privado" sin clases. 

function crearContador(inicial = 0) {
  let valor = inicial;    // variable privada del closure

  return {
    incrementar: () => ++valor,
    decrementar: () => --valor,
    ver:        () => valor,
    resetear:   () => { valor = inicial; }
  };
}

const contadorA = crearContador(5);
const contadorB = crearContador();   // cada uno con su propio estado

contadorA.incrementar();  // 6
contadorB.decrementar();  // -1
contadorA.incrementar();  // 7 (aún recuerda su "valor")
console.log(contadorA.ver()); // 7
Uso real: la variable valor queda protegida: nadie desde fuera puede reasignarla. Lo mismo explotan librerías como useState (React) en vanilla, o los módulos IIFE de hace unos años.

Patrón módulo con closure

Combinando closure + objeto devuelto obtienes un mini-módulo con API pública y estado privado. Es exactamente la idea detrás de los factory functions. 

const Carrito = function () {
  // ESTADO PRIVADO
  const items = [];

  // API PÚBLICA (expuesta)
  function agregar(producto) {
    items.push(producto);
  }
  function total() {
    return items.reduce((acc, p) => acc + p.precio, 0);
  }

  return { agregar, total };
}();   // IIFE: se ejecuta una sola vez

Carrito.agregar({ nombre: "piano", precio: 1200 });
console.log(Carrito.total());            // 1200
console.log(Carrito.items);              // undefined (privado)

    Repaso rápido

    • export comparte valores; por defecto uno por módulo; el resto, nombrados.
    • En el navegador usa <script type="module">; las rutas llevan extensión .js.
    • Un closure conserva las variables del entorno donde nació.
    • Closure + objeto devuelto = estado privado con API pública (patrón módulo).
