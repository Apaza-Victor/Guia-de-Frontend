Patrones y buenas prácticas

Cierra el tema con los principios y patrones que separan código "que funciona" de código profesional.

Principios de diseño

Antes de memorizar patrones, interioriza los principios que guían las decisiones técnicas. Son reglas cortas y fáciles de recordar que mejoran la calidad de cualquier código.

PrincipioQué diceEjemplo de aplicación
DRYNo te repitasExtraer la validación duplicada a una función validarEmail()
KISSMantenlo simplePreferir una solución clara antes que una "ingeniosa"
YAGNINo lo vas a necesitarNo anticipar funcionalidad futura sin necesidad real
SOLID (resumen)Separar responsabilidadesUna función cumple UNA tarea y se llama con un único motivo
Del lado del front: un componente o función debería poder entenderse sin leer el resto de la app. Si una función hace más de tres cosas (leer DOM + validar + guardar + pintar), divídela.

Patrón módulo (revisión) y factoría

Ya viste el patrón módulo en la lección anterior. Ahora lo consolidamos con dos variantes de uso común y las comparamos con las clases. 

// FÁBRICA (factory): función que devuelve un objeto nuevo en cada llamada
const crearTarea = (titulo, prioridad = "media") => ({
  titulo,
  prioridad,
  completada: false,
  completar() { this.completada = true; },
  resumen() {
    const estado = this.completada ? "hecha" : "pendiente";
    return `[${prioridad}] ${titulo} — ${estado}`;
  }
});

const t1 = crearTarea("Diseñar mockups", "alta");
const t2 = crearTarea("Escribir docs");
t1.completar();
console.log(t1.resumen()); // [alta] Diseñar mockups — hecha
console.log(t2.resumen()); // [media] Escribir docs — pendiente
EnfoqueCuándo elegirlo
Función fábricaObjetos simples, sin herencia; máximo control y mínima magia
ClaseNecesitas herencia, campos privados # o métodos estáticos
Patrón módulo (IIFE)Un único singleton con estado privado global (config, caché)

Nombres, comentarios y formato

// ❌ Mala legibilidad
const fn = (a, b, c) => b.length > a ? c * 1.21 : c;
// ✅ Versión legible
function calcularPrecioConIva(tipoCliente, items, base) {
  const tieneDescuento = items.length > 5;
  const iva = 0.21;
  const recargoMayorista = tipoCliente === "mayorista";

  if (tieneDescuento) {
    const precio = base - base * 0.10;
    return recargoMayorista ? precio * (1 + iva) : precio;
  }
  return base * (1 + iva);
}
  • Nombres expresivos: verbos para funciones (obtenerUsuario), sustantivos para datos (usuariosActivos).
  • 1 idea por función: si tienes que poner un "y" al explicarla, divídela.
  • Comentarios = por QUÉ, no por QUÉ. Si el código se explica solo, el comentario sobra.
  • Formato consistente: 2 espacios (como en toda esta guía), comillas simples o dobles, siempre igual.

Consistencia con el DOM y rendimiento

// ❌ Búsqueda constante en el DOM dentro de un loop
for (let i = 0; i < 100; i++) {
  document.querySelector(".item").classList.add("activo");
}
// ✅ Cachea el nodo antes del loop y usa batching
const items = document.querySelectorAll(".item");
const frag = document.createDocumentFragment();

items.forEach(it => {
  const caja = document.createElement("div");
  caja.className = "item activo";
  frag.appendChild(caja);
});
lista.appendChild(frag);   // 1 solo re-paint, no cientos
Errores de novato que debes evitar: mezclar == con ===, dejar console.log en producción, manipular el DOM en cada vuelta del bucle, y comparar arrays con === (compara referencias, no contenido).

Demo interactiva: checklist de calidad

Una pequeña herramienta que aplica los principios de la lección: un patrón módulo expone funciones puras que validan el estilo de tu código, y una fábrica crea los ítems del chequeo.

Total de checks: 4
    // Módulo analizador con funciones puras (fáciles de testear)
const AnalizadorCodigo = (function () {
  const checks = {
    espaciado: (codigo) => /\s+[=]=/.test(codigo) ? "Faltan espacios en comparación (usa ===)" : null,
    consola:   (codigo) => codigo.includes("console.log") ? "Consola incluida en producción" : null,
    estricto:  (codigo) => /\s==\s/.test(codigo) ? "Comparación suelta con ==" : null,
    semicolon: (codigo) => /\w\s*\n[^\n=]/.test(codigo) ? "Punto y coma inconsistente" : null
  };
  return {
    analizar(codigo) {
      return Object.entries(checks)
        .map(([nombre, fn]) => ({ nombre, mensaje: fn(codigo) }));
    }
  };
})();

    Checklist final

    • === siempre; == solo si sabes exactamente por qué.
    • Funciones pequeñas y con un único propósito; nombres que se lean como frases.
    • Estado privado vía closures o #campos; nada de variables globales colgadas.
    • DOM: cachea nodos, agrupa en DocumentFragment y escucha una sola vez.
    • Elige el patrón que toque: módulo para singletons, fábrica para objetos, clase si hay herencia.
