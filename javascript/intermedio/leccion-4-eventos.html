Eventos y delegación

Reacciona a clicks, teclas y formularios sin duplicar código.

addEventListener y tipos de eventos

Un evento es una señal del navegador: un click, una tecla, un envío de formulario. addEventListener registra una función que se ejecutará cuando esa señal llegue. 

// Estructura básica
boton.addEventListener('click', (e) => {
  console.log('¡Click!');
});

// Varios tipos de eventos
input.addEventListener('input', (e) => { ... });    // al escribir
form.addEventListener('submit', (e) => { ... });     // al enviar
document.addEventListener('keydown', (e) => { ... }); // teclas
card.addEventListener('mouseenter', (e) => { ... }); // hover
EventoSe dispara cuando…
clickel usuario hace clic en el elemento
inputel valor de un campo cambia (cada tecla)
submitse envía un formulario
keydownse pulsa una tecla
mouseenter / mouseleaveel cursor entra / sale del elemento
Tip: El parámetro e es el event object. Aporta datos útiles: e.target (elemento que recibió el evento), e.key (tecla pulsada) o e.clientX (posición del ratón).

preventDefault y stopPropagation

preventDefault() cancela la acción por defecto del navegador (que un <a> navegue o que un <form> refresque la página). stopPropagation() detiene que el evento "burbujee" hacia los elementos padres. 

form.addEventListener('submit', (e) => {
  e.preventDefault();   // no refrescar la página
  console.log('Enviado sin recargar');
});
Ojo: Sin preventDefault(), cada submit recarga la página y tu JavaScript "se pierde". Es el primer reflejo que debes adquirir al manejar formularios.

Delegación de eventos con closest

Los eventos burbujean: un click en un botón interno sube por sus padres hasta el documento. Aprovechamos esto poniendo UN solo addEventListener en el contenedor y averiguando quién fue e.target con e.target.closest('.selector'). Perfecto para listas con elementos que se añaden dinámicamente. 

lista.addEventListener('click', (e) => {
  const boton = e.target.closest('.btn-eliminar');
  if (!boton) return;   // no era un botón eliminar
  boton.parentElement.remove();
});
PatrónVentaja
1 listener por botónsimple, pero se descuadra con elementos dinámicos
Delegación (1 listener en el padre)funciona con elementos creados después; menos memoria

Consejo: haz clic con precisión en el texto del elemento y en su botón para ver quién es e.target:

  • Estudiar delegación de eventos
  • Un solo listener para toda la lista
Último objetivo: ninguno
Tip: Si el objetivo de tu click pudiera ser un hijo del botón (como el <i> del icono), closest sube automáticamente hasta el ancestro que tiene la clase btn-eliminar. Sin closest, delegar con e.target === algo se rompería.

Repaso rápido

  • addEventListener('evento', fn) es la forma estándar de escuchar.
  • e.preventDefault() frena la acción por defecto; e.stopPropagation() corta la burbuja.
  • En listas, delega: un solo listener en el padre + e.target.closest().
  • La delegación funciona incluso con elementos creados después (como en esta demo).
