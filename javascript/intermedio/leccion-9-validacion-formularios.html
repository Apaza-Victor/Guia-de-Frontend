Validación de formularios

Avisa al usuario antes de enviar datos incorrectos: nativo primero, a medida después.

Atributos HTML5: validar sin JavaScript

El navegador ya valida por ti con atributos como required, minlength, pattern, type="email"… Obtienes mensajes nativos gratis: 

<input type="email" required>
<input minlength="8" pattern="[A-Za-z0-9]+">
AtributoQué valida
requiredque no esté vacío
minlength / maxlengthlargo del texto
min / maxrango en números y fechas
patternexpresión regular
typeformato: email, url, number…
Tip: Si el formulario ya valida con HTML5, no añadas JavaScript para lo mismo. Usa JS solo para requisitos a medida (contraseñas iguales, cupones, comprobaciones contra el servidor…).

Constrain Validation API

Es el puente entre los atributos nativos y JavaScript. Dos herramientas esenciales: 

const form = document.querySelector('form');
const email = document.querySelector('#email');

email.validity.valueMissing;  // true si required y está vacío
email.validity.typeMismatch; // true si el formato no es email
form.checkValidity();        // true/false del formulario completo
form.reportValidity();       // igual + muestra los globos nativos

El objeto validity tiene un campo por cada regla:

  • valueMissing — campo requerido vacío
  • typeMismatch — formato incorrecto
  • patternMismatch — no coincide con pattern
  • tooShort / tooLong — longitud
  • rangeUnderflow / rangeOverflow — fuera de rango

Mensajes a medida: setCustomValidity

Para reglas más allá de HTML5, usa setCustomValidity: al ponerle un mensaje el campo deja de ser válido, y al poner '' lo vuelves válido: 

confirmar.addEventListener('input', () => {
  if (confirmar.value !== password.value) {
    confirmar.setCustomValidity('Las contraseñas no coinciden');
  } else {
    confirmar.setCustomValidity('');
  }
});
Ojo: Si no reseteas a '' el mensaje queda "pegado" y el campo nunca podrá volver a ser válido. Resetea siempre en el evento input.

Validación en vivo (feedback temprano)

La mejor UX avisa mientras escribes, no al pulsar enviar. Escucha el evento input y pinta el error al instante: 

campo.addEventListener('input', () => {
  if (campo.validity.valueMissing) {
    mensaje.textContent = 'Este campo es obligatorio';
  } else {
    mensaje.textContent = '';
  }
});
Tip: Los mensajes grandes se muestran mejor bajo el campo que dentro del globo nativo. Puedes usar reportValidity() solo en el envío y guardar la validación en vivo para tu propio diseño.

Demo: registro con validación a medida

Formulario que combina todo: required nativo, confirmación de contraseña con setCustomValidity y validación en vivo.

Ojo: La validación del cliente es UX, no seguridad. Un usuario con DevTools puede enviar lo que quiera; el servidor siempre debe validar de nuevo.

Repaso rápido

  • Empieza siempre por los atributos HTML5: validan gratis.
  • validity te dice cuál regla falla; checkValidity() dice si falla algo.
  • setCustomValidity('msg') para reglas a medida; '' las rehabilita.
  • Valida en vivo con input y muestra el error bajo el campo.
  • Lo que valida JS es UX: el backend es quien manda.
