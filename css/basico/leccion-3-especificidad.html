Cascada y herencia

Descubre el mecanismo exacto que decide qué regla gana y qué propiedades se transmiten a los elementos hijos.

Fundamentos de la lección

Cuando dos reglas apuntan al mismo elemento, el navegador no se adivina: aplica un algoritmo de cascada. Esta lección te enseña a predecir siempre quién gana, combinando especificidad, herencia y orden de aparición.

(0,0,1) Herencia !important

¿Cómo gana una regla?

La cascada resuelve los conflictos en este orden, de menor a mayor prioridad:

  1. Estilos del navegador — valores por defecto (user-agent).
  2. Estilos de usuario — opciones del propio navegador (p. ej. tamaño de fuente).
  3. Autor — el CSS que escribes tú.
  4. Especificidad — dentro del mismo origen, gana el selector con más peso.
  5. Orden de aparición — a igual especificidad, gana la última regla escrita.
  6. !important — da prioridad absoluta sobre los pasos anteriores (salvo otro !important).

En la práctica, con CSS propio solo necesitas dominar los tres últimos puntos: especificidad, orden y !important.

Tip: si dos reglas idénticas conflictúan y no sabes por qué gana una, busca en DevTools la pestaña Styles: ahí se ven ambas y cuál está tachada.

Especificidad: etiqueta < clase < id

Cada selector acumula un peso representado como (a, b, c):

  • a = número de id.
  • b = número de clases, atributos y pseudo-clases.
  • c = número de etiquetas y pseudo-elementos.

Se comparan de izquierda a derecha: gana el primer valor mayor. Es la notación que usan las herramientas de desarrollo.

p { color: #64748b; }           /* (0,0,1)  — etiqueta */
.card { color: #2563eb; }         /* (0,1,0)  — clase  */
#hero { color: #06b6d4; }       /* (1,0,0)  — id     */

Un id gana a cualquier cantidad de clases; una clase gana a cualquier cantidad de etiquetas. El orden nunca depende del número de líneas, sino de la columna que sea mayor.

SelectorDesgloseNotaciónPeso (base 100)
p1 etiqueta(0,0,1)1
.card p1 clase + 1 etiqueta(0,1,1)11
#hero h11 id + 1 etiqueta(1,0,1)101
button.btn:hover1 etiqueta + 2 clases/pseudo(0,2,1)21
Cuidado: Los combinadores (>, +, ~, espacio) y el selector universal * no suman especificidad. #hero p y #hero > p pesan igual: (1,0,1).

Herencia: qué pasa si nadie gana

Cuando un elemento no recibe una propiedad (ni por regla ni por especificidad), el navegador comprueba si esa propiedad se hereda del padre.

Se heredanNo se heredan
color, font-family, font-size, line-height, text-align, letter-spacing margin, padding, border, background, width, height, display

Con las palabras clave inherit e initial controlas la herencia manualmente:

.enlace-muted {
  color: inherit;   /* toma el color del padre, olvida el azul del <a> */
}

.parrafo {
  margin: initial;  /* vuelve al comportamiento por defecto */
}

Bonus: unset actúa como inherit si la propiedad es heredable y como initial si no lo es.

!important: la salida de emergencia

!important coloca una declaración por encima de toda la especificidad y el orden de aparición. Es potente y peligroso: dos !important en conflicto vuelven a decidirse por especificidad. 

.etiqueta {
  color: #0ea5e9 !important;
}

#hero {
  color: #06b6d4;  /* pierde contra el !important */
}
Advertencia: El !important rompe la previsibilidad y dificulta el mantenimiento. Úsalo solo para sobreescribir estilos de librerías de terceros o como último recurso. En tus propios estilos, usa especificidad bien pensada.

Repaso rápido

  • La cascada decide así: origen → especificidad → orden → !important.
  • Especificidad en (a, b, c): id > clase > etiqueta. Un id gana a todas las clases.
  • Los combinadores y * no suman peso.
  • El color y la tipografía se heredan; el layout (margin, padding, border) no.
  • Usa inherit, initial o unset para forzar la herencia cuando quieras.
  • Reserva !important para librerías de terceros: tu especificidad bien escrita lo evita.
