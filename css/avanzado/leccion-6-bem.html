Metodología BEM y arquitectura

Nombra tus clases como una profesional: bloques, elementos y modificadores para un CSS escalable y predecible.

¿Qué es BEM?

BEM (Block, Element, Modifier) es una convención de nombres que organiza el CSS en bloques reutilizables, sus elementos internos y sus variaciones (modificadores). El patrón de nombre es: 

.bloque__elemento--modificador

/* Ejemplo real: una tarjeta de producto */
.tarjeta              /* bloque              */
.tarjeta__imagen     /* elemento (imagen)  */
.tarjeta__titulo     /* elemento (título)  */
.tarjeta__boton      /* elemento (botón)   */
.tarjeta__boton--ok  /* mod. del botón     */
.tarjeta--destacada  /* mod. del bloque    */
FamiliaNombreSignificado
Bloque.tarjetaComponente autónomo y reutilizable
Elemento.tarjeta__tituloParte que solo tiene sentido dentro del bloque
Modificador.tarjeta--destacadaVariación de estado o apariencia

Dos guiones bajos separan bloque de elemento; dos guiones separan el modificador. El objetivo: especificidad plana (una clase = un selector), sin anidamientos infinitos ni reglas !important.

Bloques versus elementos

Un bloque es un componente independiente que podría vivir en cualquier parte del sitio sin perder sentido. Un elemento solo existe dentro de su bloque: .menu__enlace no significa nada fuera de .menu. Por eso BEM prohíbe nombrar elementos globales. 

/* Bloques anidados: cada uno conserva su propio vocabulario */
<header class="cabecera">
  <nav class="menu">
    <a class="menu__enlace menu__enlace--activo" href="#">Inicio</a>
  </nav>
</header>

Nótese que el estado "activo" es un modificador independiente: semanas después, cambiar el estado activo del menú no toca el HTML hijo, solo la clase que lleva.

BEM en la práctica: un componente real

Los modificadores cambian el aspecto de un bloque o elemento sin duplicar estilos. Observa cómo una variante "destacada" sobreescribe únicamente lo que necesita: 

/* CSS: base + variante, sin cascada "accidental" */
.tarjeta             { background: #fff; border-radius: 1rem; padding: 1rem; }
.tarjeta--destacada { border: 2px solid #2563eb; box-shadow: 0 12px 30px rgba(37, 99, 235, 0.35); }

/* HTML: dos clases que se complementan */
<article class="tarjeta tarjeta--destacada"> … </article>
Tip: los modificadores se añaden, nunca sustituyen la clase base. El tema abre el bloque y el modificador lo ajusta, lo que te permite cambiar todo el componente tocando un solo archivo.

Especificidad plana y buenas prácticas

La mayor ventaja de BEM no es estética: es que todos tus selectores pesan exactamente lo mismo (una clase). Cuando dos reglas empatan, gana la que aparece después en el CSS, así que el resultado depende del orden, nunca de un selector más largo. Resultado: CSS más predecible, más barato de mantener y sin !important. 

/* ✗ Especificidad creciente e impredecible */
.sidebar nav ul li a:hover { … }

/* ✓ Una clase por nivel: plana y reutilizable */
.menu            { … }
.menu__enlace    { … }
.menu__enlace:hover { … }
.menu__enlace--activo { … }
  • Evita anidar elementos: .menu__item__enlace es difícil de leer. Prefiere .menu__item + .menu__enlace.
  • Un elemento dentro de un modificador (.menu__enlace--activo) se escribe pegado al bloque del que depende.
  • Los estados de JS (clases is-*) se reservan como marcadores; BEM describe estructura, no comportamiento.
Ojo: BEM puede parecer verboso (.tarjeta__titulo vs. .titulo). Es un precio a pagar consciente: los nombres largos se escriben una vez si usas CSS Modules, preprocesadores o plantillas que reutilizan la clase.

Repaso rápido

  • BEM: bloque__elemento--modificador para especificidad plana y componentes reutilizables.
  • Los elementos solo existen dentro de su bloque; los modificadores se añaden a la clase base.
  • Todos los selectores pesan lo mismo: el orden del CSS decide, no la longitud del selector.
  • No anides elementos, no uses !important y reserva las clases is-* como marcadores de JS.
