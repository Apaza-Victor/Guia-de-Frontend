Git y GitHub desde cero

Qué es el control de versiones, los comandos esenciales de Git y cómo colaborar con GitHub.

¿Qué es el control de versiones?

El control de versiones es un sistema que registra los cambios realizados en archivos a lo largo del tiempo, para poder recuperar versiones anteriores, comparar differencias y trabajar en equipo sin pisarse los cambios.

Imagina escribir un ensayo. Sin control de versiones:

Ensayo_final.doc

final_v2_real.docx ... ¿cuál es la buena?

Con Git

Historial limpio, cada cambio tiene autor y fecha

Con GitHub

Todo en la nube, el equipo colabora en paralelo

Configuración inicial

Antes de empezar, configura tu identidad en Git (esto firma cada commit que hagas):

# Configurar nombre y correo (una sola vez)
git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"

# Verificar configuración
git config --list
Tip: El flag --global aplica la configuración a todos los repositorios de tu máquina. Si lo omites, solo aplica al repositorio actual.

Comandos fundamentales

Estos son los comandos que usarás todos los días:

# Crear un repositorio nuevo
git init

# Agregar archivos al área de preparación (staging)
git add .                # todos los archivos
git add index.html      # un archivo específico

# Confirmar cambios con un mensaje
git commit -m "Mensaje descriptivo"

# Ver el estado del repositorio
git status

# Ver el historial de commits
git log --oneline
Comando¿Qué hace?Cuándo usarlo
git initCrea un repositorio vacío en la carpeta actualUna vez, al empezar un proyecto
git add .Mueve todos los cambios a la zona de preparaciónAntes de cada commit
git commit -m "..."Guarda un snapshot con mensaje descriptivoCada vez que completes una tarea lógica
git statusMuestra qué archivos están modificados, staged o sin rastrearConstantemente, para verificar estado
git log --onelineMuestra historial comprimido (un commit por línea)Para revisar qué se ha hecho
Importante: Un commit debe representar una tarea completa y coherente. No hagas commits con mensajes como "fix" o "cambios" — sé descriptivo: "Agrego validación del formulario de contacto".

Ramas (branches) y merge

Las ramas te permiten trabajar en una funcionalidad nueva sin afectar el código principal (main). Cuando terminas, fusionas (merge) la rama en main. 

# Crear y cambiar a una rama nueva
git checkout -b feature-login

# (hacer cambios y commits en la rama)
git add .
git commit -m "Implemento formulario de login"

# Volver a main y fusionar
git checkout main
git merge feature-login

# Ver todas las ramas
git branch -a
Tip: Si surge un conflicto durante merge, Git te marcará las líneas en conflicto. Edita el archivo, elige qué mantener y haz un nuevo commit.

Push, Pull y Clone

Estos comandos conectan tu repositorio local con GitHub (o cualquier servidor remoto):

Comando¿Qué hace?Ejemplo
git cloneCrea una copia local de un repositorio remotogit clone https://github.com/user/repo.git
git remote add originConecta un repositorio local con uno remotogit remote add origin https://github.com/user/repo.git

# Primer push: subir proyecto existente a GitHub
git remote add origin https://github.com/tu-usuario/mi-proyecto.git
git branch -M main
git push -u origin main

.gitignore

El archivo .gitignore le dice a Git qué archivos o carpetas no debe rastrear. Esto es esencial para no subir archivos pesados, datos sensibles o generados automáticamente. 

# .gitignore
node_modules/         # dependencias de npm
dist/                 # archivos compilados
.env                  # variables de entorno (API keys)
*.log                 # archivos de log
.DS_Store             # macOS system files
Nunca subas: .env, node_modules/, o cualquier archivo con contraseñas, tokens o API keys a un repositorio público.

Flujo típico de un día con Git

1. Clonar el repositorio (primera vez)
git clone https://github.com/equipo/proyecto.git

2. Crear rama para tu tarea
git checkout -b feature-header-responsive

3. Hacer cambios, guardarlos
git add .
git commit -m "Agrego diseño responsive al header"

4. Subir tu rama a GitHub
git push -u origin feature-header-responsive

5. Crear Pull Request en GitHub y pedir review

6. Después del merge, volver a main y actualizar
git checkout main
git pull origin main

Repaso rápido

  • Git es un sistema de control de versiones distribuido: cada desarrollador tiene una copia completa.
  • El ciclo básico es: add → commit → push.
  • Las ramas permiten desarrollar features aisladas y fusionarlas después.
  • GitHub es la plataforma remota donde se almacenan y colabora en repositorios.
  • El archivo .gitignore evita subir archivos no deseados.
