npm y automatización

El gestor de paquetes de Node, tu package.json, scripts y la automatización del flujo frontend.

¿Qué es npm?

npm (Node Package Manager) es el gestor de paquetes predeterminado de Node.js. Es el encargado de instalar, actualizar y eliminar las librerías y herramientas que tu proyecto necesita (Bootstrap, GSAP, Sass, Vite…), gestionando sus versiones automáticamente.

npm viene instalado junto con Node.js. Verifica tu versión:

node -v     # versión de Node.js
npm -v      # versión de npm

Todo gira alrededor del registro público de npm (npmjs.com), un enorme catálogo con más de 2 millones de paquetes. Al instalar un paquete, npm lo descarga a tu carpeta node_modules.

node_modules y package.json

node_modules es donde se guardan las dependencias instaladas. Es enorme y nunca se edita a mano.

package.json es el "documento de identidad" del proyecto: lista dependencias, scripts y metadatos.

// package.json (ejemplo)
{
  "name": "mi-proyecto",
  "version": "1.0.0",
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  },
  "dependencies": {
    "bootstrap": "^5.3.3"
  },
  "devDependencies": {
    "sass": "^1.77.0"
  }
}
Tip: node_modules nunca se sube a Git: por eso tu .gitignore lo excluye. Cualquiera puede reconstruirlo ejecutando npm install usando solo el package.json.

npm init e npm install

# Crear un nuevo package.json interactivo
npm init -y         # responde "sí" a todo (crea el archivo directo)

# Instalar dependencias de producción
npm install bootstrap

# Instalar dependencias de desarrollo (-D o --save-dev)
npm install -D sass vite

# Instalar una herramienta global (accesible en cualquier carpeta)
npm install --global create-vite
ModoFlagSe guarda enEjemplo típico
Producción(ninguno)dependenciesBootstrap, React, GSAP (lo usa el sitio)
Desarrollo-D / --save-devdevDependenciesSass, Vite, ESLint (solo herramientas)
Global--global / -gSistema (no en el proyecto)CLIs como create-vite
Cuidado: Prefiere dependencias locales a globales. Una dependencia global puede tener una versión distinta en la máquina de cada persona; node_modules garantiza exactamente la misma versión para todos.

Scripts: tu automatización diaria

Los scripts son comandos abreviados definidos en package.json. Con npm run los ejecutas con un solo nombre:

// package.json → scripts
{
  "scripts": {
    "dev":    "vite",
    "build":  "vite build",
    "preview":"vite preview",
    "sass":   "sass src/styles:dist/styles --watch"
  }
}
# Ejecutar los scripts
npm run dev          # servidor de desarrollo en localhost
npm run build        # genera la versión final optimizada
npm run sass         # compila Sass de forma continua
ScriptPropósitoSalida
npm run devEntorno de desarrollo con recarga en vivoServidor local + hot reload
npm run buildEmpaqueta y optimiza el sitioCarpeta dist/ lista para publicar
npm run previewSirve localmente el build producidoComprueba la versión final

Bundlers: empaquetando tu código

Un bundler toma todos tus archivos (JS, CSS, imágenes, fuentes), los analiza, resuelve dependencias y los combina en pocos archivos optimizados que el navegador puede cargar fácilmente.

index.js + utils.js + styles.scss + logo.svg dist/assets/app.8f3a22.js
HerramientaTipo¿Para qué?

WebpackBundlerEl clásico, muy configurable (usado por proyectos legacy)

Crear un proyecto con Vite es literalmente un comando:

npm create vite@latest mi-app -- --template vanilla
cd mi-app
npm install
npm run dev

Repaso rápido

  • npm gestiona paquetes de JavaScript; package.json guarda la lista de dependencias y scripts.
  • npm install reconstruye node_modules desde package.json.
  • Usa -D para herramientas de desarrollo y --global solo para CLIs.
  • Los scripts (dev, build) automatizan tu día a día.
  • Un bundler (como Vite) empaqueta y optimiza tu código para producción.
