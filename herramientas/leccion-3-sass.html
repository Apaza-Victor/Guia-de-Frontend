Sass: preprocesador CSS

Escribe CSS más limpio con variables, anidación, mixins y partials, y compila todo a CSS nativo con la CLI de Sass o desde npm.

¿Qué es Sass?

Sass (Syntactically Awesome Style Sheets) es un preprocesador de CSS: te deja escribir estilos con superpoderes (variables, anidación, mixins y funciones) que no existen en CSS puro. Después, un compilador traduce todo a CSS estándar que cualquier navegador entiende.

Existen dos sintaxis: .scss (la moderna, un superconjunto de CSS: si sabes CSS ya sabes SCSS) y .sass (indentada, sin llaves). En esta guía usamos SCSS.

SintaxisExtensiónEstilo¿Cuándo?
SCSS.scssIgual que CSS, con { } y ;El estándar actual, recomendado
Sass.sassIndentado, sin llaves ni punto y comaProyectos legacy o equipos que la prefieren
Tip: Todo CSS válido es también SCSS válido. Puedes renombrar un archivo .css a .scss y seguir compilando sin errores.

Variables: tu paleta centralizada

Las variables de Sass empiezan con $ y evitan repetir valores mágicos. Cambias el color en un solo lugar y todo el proyecto se actualiza. 

// _variables.scss — definir
$color-primario: #2563eb;
$color-fondo: #0f172a;
$espaciado-base: 1rem;
$radio-redondeado: 12px;

// main.scss — usar
.boton {
  background: $color-primario;
  color: #fff;
  padding: $espaciado-base 1.5rem;
  border-radius: $radio-redondeado;
}
Recuerda: Las variables solo existen en tiempos de compilación. El CSS final no contiene $color-primario, ya está reemplazada por su valor.

Anidación: refleja tu HTML

Sass permite anidar selectores para reflejar la jerarquía del HTML y usar el selector padre (&) para pseudo-clases como :hover. 

.card {
  padding: 1.5rem;
  border-radius: 16px;

  &:hover {                    /* .card:hover */
    transform: translateY(-4px);
  }

  .card-title {                  /* .card .card-title */
    font-weight: 700;
  }
}

El CSS compilado conserva los selectores finales, así que el resultado es 100% compatible con tu HTML.

Tip: No anides más de 3 o 4 niveles. El anidamiento profundo genera CSS largo y difícil de depurar.

Mixins e @include

Un mixin es un bloque de estilos reutilizable que puedes parametrizar. Se define con @mixin y se aplica con @include. 

@mixin boton-estilo($color, $radio: 10px) {
  background: $color;
  border: none;
  border-radius: $radio;
  padding: .6rem 1.4rem;
  font-weight: 600;
}

.boton-primario {
  @include boton-estilo(#2563eb);            /* radio usa el valor por defecto */
}

.boton-peligro {
  @include boton-estilo(#ef4444, 18px);
}
DirectivaPara qué sirve
@mixin nombre(...)Define un bloque reusable, opcionalmente con parámetros
@include nombre(...)Inserta el mixin en el selector actual
Tip: Usa mixins para estilos que se repiten con variaciones. Para simple reutilización de valores, una variable suele bastar.

Funciones integradas

Sass trae decenas de funciones para transformar colores, números y strings sin escribir CSS extra:

FunciónQué haceEjemplo
darken()Oscurece un colordarken(#2563eb, 10%)
lighten()Aclara un colorlighten(#2563eb, 10%)
mix()Mezcla dos coloresmix(#fff, #2563eb, 70%)
rgba()Aplica transparenciargba(#2563eb, 0.5)
percentage()Convierte a porcentajepercentage(0.75) → 75%
 
.boton {
  background: $color-primario;
  border-radius: percentage(.1);   /* compila a border-radius: 10%; */

  &:hover {
    background: darken($color-primario, 10%);
  }
}

Partials y @use: organiza tu código

Un partial es un archivo SCSS cuyo nombre empieza con guion bajo (_variables.scss) y que no genera CSS propio: solo se importa. Con @use lo cargas y accedes a su contenido por namespace. 

scss/
  main.scss          // entrada principal
  _variables.scss    // partial de variables
  _mixins.scss       // partial de mixins
  _base.scss         // estilos base
// main.scss
@use 'variables';
@use 'mixins';
@use 'base';

.boton {
  background: variables.$color-primario;   /* namespace + variable */
  @include mixins.boton-estilo(#2563eb);
}
Tip: @use reemplazó al antiguo @import. Solo usa @use en proyectos nuevos para evitar problemas de alcance global.

Compilar con Sass CLI y npm

Con Dart Sass instalado (viene como paquete npm) compilas desde la terminal. Instálalo como dependencia de desarrollo:

# Instalar el compilador en el proyecto
npm install -D sass

# Compilar un archivo: entrada.scss:salida.css
npx sass scss/main.scss:dist/css/main.css

# Compilar carpetas enteras, en modo watch y minificado
npx sass scss:dist/css --watch --style=compressed

La forma profesional es añadirlo como script en tu package.json:

// package.json → scripts
{
  "scripts": {
    "sass": "sass scss:dist/css --watch --style=compressed"
  }
}
# Ejecutar: npm run sass
Ojo con --watch: El modo --watch se queda activo escuchando cambios. Deja esa terminal abierta en tu editor y olvídate de compilar a mano.

Repaso rápido

  • Un preprocesador extiende CSS con lógica: variables, anidación, mixins y funciones.
  • Usa .scss y organiza tu código en partials (_archivo.scss).
  • Las variables $nombre centralizan valores; los mixins reutilizan bloques con @include.
  • Funciones como darken() y mix() transforman colores al compilar.
  • Compila con Dart Sass: npm install -D sass y un script "sass": "sass scss:dist/css --watch".
